What you can build

The API speaks Siren ({{sirenMediaType}}), a hypermedia format: every answer carries the links and actions you can take next. Articles also come as Markdown documents ({{markdownMediaType}}).

An integration acts for one reader, who approves it with their Readplace account. Create an account to try it.

A typical integration is a scheduled job that drains a readlist: it lists what's in it, reads each article as Markdown, hands it on, then takes it out of the readlist. The walkthrough at the end follows that flow. Nothing is pushed to you, so the job polls.

Readplace's own apps use the same API:

Register your app and get a token

Readplace is its own OAuth 2.0 authorization server. Its metadata is at /.well-known/oauth-authorization-server, and the protected resource metadata at /.well-known/oauth-protected-resource points to it.

Register

Register once with Dynamic Client Registration (RFC 7591): send a POST with JSON to /oauth/register.

  • Each redirect URI is https, on any host (https://localhost included), or plain http on 127.0.0.1 or [::1]. http://localhost and custom schemes are refused with 400 invalid_redirect_uri.
  • redirect_uris holds 1 to 32 URIs of up to 2,048 characters each.
  • client_name is optional and up to 120 characters, and the reader sees it when approving your app. Without it, Readplace names your app after the host of the first redirect URI, without its port.
  • There's no client secret. If you send token_endpoint_auth_method, it must be none.
  • The 201 answer carries your client_id. Sending the same registration again returns the same client_id.
  • A registration that never gets a token expires after {{idleRegistrationHours}} hours. Once it has one, it stays registered until {{activeRegistrationDays}} days after its latest token, refreshes included.
  • /oauth/register and /oauth/token limit how often one IP address can call them. Over the limit, they answer 429 with a Retry-After header.
POST /oauth/register HTTP/1.1
Host: readplace.com
Content-Type: application/json

{"redirect_uris": ["http://127.0.0.1:8765/callback"], "client_name": "Reading automator"}

Authorize

Send the reader's browser to /oauth/authorize with a PKCE challenge, using S256. Readplace asks the reader to sign in if needed and to approve your app, then redirects to your redirect URI with code and state.

redirect_uri must match a registered URI exactly, port included, so register the exact loopback port your app listens on.

Leave out scope. Every token gets full access to the reader's account, and a refresh that sends scope is refused with 400 invalid_scope. The protected resource metadata lists that one access level in scopes_supported as {{scopeLabel}}.

resource is optional, because Readplace is both the authorization server and the API, so every token it issues is already for this API.

GET /oauth/authorize?response_type=code&client_id=CLIENT_ID&redirect_uri=REDIRECT_URI&code_challenge=CODE_CHALLENGE&code_challenge_method=S256&state=STATE HTTP/1.1
Host: readplace.com

Get tokens

Exchange the code with your PKCE verifier:

The answer is JSON with access_token, refresh_token, token_type and expires_in.

Access tokens are short-lived. Read expires_in from each token answer, and refresh when a request answers 401 with invalid_token.

Refresh tokens last {{refreshTokenDays}} days and rotate: every refresh returns a new pair and retires the refresh token you sent. Store the new pair before you use it.

  • A refused refresh answers JSON with error and readplace_reason, with status 400. A refused code exchange answers JSON with error and error_description.
  • invalid_grant means the grant is gone: the refresh token was already used, has expired or was revoked, or the reader signed your app out from all devices or changed or reset their password. Send the reader through authorize again.
  • invalid_client means no registration that allows refresh exists for your client_id: it expired, or it was registered without the refresh_token grant. Register again, leaving grant_types out.
  • 503 with temporarily_unavailable means try again later with the same refresh token.
POST /oauth/token HTTP/1.1
Host: readplace.com
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&code=AUTH_CODE&redirect_uri=REDIRECT_URI&client_id=CLIENT_ID&code_verifier=CODE_VERIFIER
POST /oauth/token HTTP/1.1
Host: readplace.com
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token&refresh_token=REFRESH_TOKEN&client_id=CLIENT_ID

Disconnect

/oauth/revoke takes an access token or a refresh token, and revoking either drops the other too. Readers can also disconnect your app under Connected apps in their account.

Connected apps lists your app as AI assistant, connected from the host of your first redirect URI, or from an app on your computer when that URI is on 127.0.0.1 or [::1]. A client_name that matches a supported assistant's name, in any letter case, lists your app as that assistant instead.

create-session, on every collection, answers 204 with a browser session cookie, for an app that opens Readplace's reader in its own web view. Most integrations skip it. Revoking the token, or the reader disconnecting your app, doesn't end a session it made, so clear the cookie from your web view when your app is disconnected. A password change or reset does end it.

create-browser-handoff, on every collection, answers 200 with a single-use, short-lived code. A browser that opens the handoff page with that code is signed in as the reader. Most integrations skip it.

report-age-range, on every collection, is how Readplace's own apps pass on the age range a device's app store reports for its user. It answers 204, or 403 when that user may not use Readplace. Integrators skip it.

POST /oauth/revoke HTTP/1.1
Host: readplace.com
Content-Type: application/json

{"token": "REFRESH_TOKEN"}

Start from one URL

Every request carries the reader's access token and the Siren media type. Start at /.

It answers 200 with the reader's collection, not a redirect:

  • Hard-code only /, the two media types, the action names you use, what the fields you fill in mean, the link rels you follow, and the frontmatter keys you read. Read everything else from the answers: every href, method, type and field list. Encode each body as the action's type says, and build it from the action's fields rather than a hard-coded encoding.
  • Treat every href as opaque. Follow it or submit to it as given, and never build or edit one.
  • Skip what you don't recognise. New actions, links and properties can appear at any time.
  • If a request to an href or action you kept fails with anything other than a 401, 403 or 422 refusal, such as a 404 or 405, drop your copy, start again from / and retry once.
  • Links use the IANA rel where one exists, such as self, next and prev. original is Memento's. read, upload-again, root, account, add-links-help and upload are Readplace's own.
  • An entity's class says what it is: collection and articles on a collection, article on an article, error on a refusal and on a 409, save-articles-result on a save-articles answer, upload-slot on an upload slot, and upload and upload-staged on the upload entry and a staged upload.
{{#if variants.discovery}}{{variants.discovery}}{{else}}GET / HTTP/1.1
Host: readplace.com
Authorization: Bearer ACCESS_TOKEN
Accept: {{sirenMediaType}}{{/if}}
HTTP/1.1 200 OK
Content-Type: {{sirenMediaType}}

Read a collection

A collection is one page of a readlist's articles, in one tab. Its entities are the articles, and its properties link to the rest:

    {{#each collectionProperties}}
  • {{name}}: {{{description}}}
    • {{/each}}

Other links serve Readplace's own apps, so ignore the ones you don't use.

A next link can carry a class of offline-prefetch. It tells Readplace's own apps how to load that page while they download a readlist for offline reading, so ignore it.

A page past the last answers 200 with no entities, a prev link and no next link.

search lists articles with these fields:

    {{#each searchFields}}
  • {{name}}: {{{description}}}
    • {{/each}}

A value Readplace doesn't accept is dropped, not refused. search always lists All, so inside a named readlist, follow its tabs and pages hrefs instead.

Read an article

Each article entity carries these properties:

    {{#each articleProperties}}
  • {{name}}: {{{description}}}
    • {{/each}}

Each article entity also carries a self link with no title: the article's own address. Fetch it to get that article alone.

An article whose source is public also carries an original link of type text/html, with no title: the page it came from, to open in a browser without the token. An uploaded file or other private item has none, even though its url is set. An upload Readplace couldn't use carries an untitled upload-again link of type text/html to the signed-in upload page, until the next version of the article drops it. Show each only while it's present.

Follow an article's read link with the token and the Markdown media type to get the article as a document:

Check the status first, then the Content-Type, because the 401 and 404 answers have Markdown bodies too. A 404 means the article isn't this reader's.

The document opens with YAML frontmatter. A key whose value is absent is left out, never null:

    {{#each frontmatterKeys}}
  • {{name}}: {{{description}}}
    • {{/each}}

A document is final once readplace_content_status is failed or not-an-article, or it's ready and readplace_summary_status is ready, failed or skipped. Fetch an incomplete one again later. Final isn't frozen: read state, readlist membership and a re-crawl still change it.

After the frontmatter comes the summary as a callout, > [!summary] Summary (TL;DR) with the summary quoted beneath it, then the article as Markdown. The callout is there only when readplace_summary_status is ready, and the article is empty until readplace_content_status is ready.

When the reader has highlighted the article, the document ends with a ## Highlights section: each highlight as a quote, followed by the reader's note when there is one. A quote whose passage changed in the current version ends with (edited in the current version; you highlighted “…”), and one whose passage is gone ends with (not found in the current version).

GET READ_HREF HTTP/1.1
Host: readplace.com
Authorization: Bearer ACCESS_TOKEN
Accept: {{markdownMediaType}}

Save links and pages

save-article saves a link, and every save lands in All. To file it in other readlists too, send their hrefs from properties.readlists in its readlists field, which takes several values, as an array in JSON, up to the field's maxItems. A save from a named readlist's collection also files it in that readlist.

  • 201: the saved article, with messages to show and a collection link, and a Location header with the same address as the article's self link. Saving a link again answers 201 too, with a message that it was already saved.
  • 409: Readplace accepted the save and is still finding the original article behind a wrapper link, such as a redirect or tracking link. It isn't a failure, though the body is an entity of class error: its one warning message says the link is queued. The article appears later. Show the message and don't send the save again: each resubmission starts another save.
  • 422 with an error entity whose code is invalid-url: the URL is malformed.
  • 422 with the collection and a warning of {code, message}: Readplace can't reach that URL, such as a file: link or a local address. That collection isn't scoped to a tab and isn't meant for paging.
  • 500 with save-failed: try again later.

save-articles saves up to {{bulkPageCount}} pages in one multipart request. Its manifest field holds a JSON array of {url, title, mediaType}, where title and mediaType are optional, and each page whose entry has a mediaType sends its bytes in a file part of its own. It answers 422 with an error entity when the body isn't multipart or the manifest is malformed (invalid-save-articles), the manifest lists more than {{bulkPageCount}} pages (save-articles-too-many-pages), or the request is over {{requestLimit}} (save-articles-too-large).

Name each page's part content- followed by the page's index in the manifest, counting from 0, such as content-0. The action's content field names that family of parts and gives each part's maxBytes.

A page is saved as a link alone, and still counts as created or merged, when its part is missing, its mediaType isn't HTML or PDF, its bytes say PDF without a PDF header, or its URL isn't an article, such as a webmail page.

The 200 answer is an entity of class save-articles-result. saved, queued, skipped and failed count pages, where saved includes the queued ones. skippedUrls lists each skipped page as {url, code, message}, and tooBig is always an empty list. results holds a {url, outcome, code} for each manifest entry, in manifest order. outcome is created, merged, skipped or failed. code is queued on a page Readplace is still resolving behind a wrapper link, or says why a page was skipped: unsupported_scheme, private_network, malformed_url or private_item.

save-articles files every page into All and records each one as a page the reader chose, so send only pages a reader picked.

save-content saves a page or file you already hold, so Readplace keeps what the reader saw. It's a multipart request with url, content (the file), mediaType (text/html or application/pdf), an optional title, and captureTrigger. It files into All only, and answers 201 with the saved article, or 409 as save-article does.

When content holds the bytes, a mediaType other than HTML or PDF, a URL that isn't an article, or a PDF without a PDF header doesn't refuse the save: it answers 201 and saves the link alone.

captureTrigger is automatic or manual, and any other value answers 422 invalid-save-content with the message captureTrigger must be automatic or manual. Send automatic for any capture no reader tapped: Readplace weighs it like a copy it fetched itself, so it can be set aside as unreadable. manual, or no captureTrigger, counts as a capture the reader chose, which Readplace keeps when it's the article's first content.

For a file over the content field's maxBytes, send size in bytes instead of content. The answer is an upload slot with an expiresAt and two actions:

  1. upload-content: PUT the file, exactly the size you declared, to its href, with the action's type as the Content-Type, before expiresAt. The href is a signed upload address, so it needs no token.
  2. save-uploaded-content: submit it with the values its fields carry.

The slot answers 200. Submit save-uploaded-content within 30 minutes of finishing the upload: after that it answers 422 upload-not-found, and you start again with a new slot. A size request for a wrapper link whose original article Readplace can't find yet answers 422 original-unresolved, where sending the bytes in content would answer 409.

A file saved through an upload slot counts as a capture the reader chose, whatever captureTrigger the save-content request sent, so use one only for a file a reader picked.

A refused save-content answers 422 with an error entity and a fallback save-article action that saves the link alone. The codes are invalid-save-content, capture-not-allowed, unsupported-media-type, content-too-large, original-unresolved, upload-not-found and not-a-pdf, which save-uploaded-content answers when the uploaded file isn't a PDF. capture-not-allowed, for a URL that isn't an article, and unsupported-media-type come only from a request that sends size or completes an upload. With the bytes in content, the same cases answer 201 and save the link alone.

A 201 save answer, a 409, and the 402 and 403 refusals carry messages for the reader. Show each one as given, because its body is HTML. Every other refusal is an error entity with a code to key off and a plain-text message, except the 422 collection with a warning above, and the 406 and 429 under Errors.

Upload books, audio and video

Every collection carries an upload link with no title. Follow it with the token to reach the upload entry, which keeps a file only the reader can open, not a page at a URL.

The entry is an entity of class upload. properties.kinds lists the kinds of file this reader can upload, each with its name (book, audio or video), a description to show, accepts (each media type with its file extensions), uploadCeilingBytes and ceilingLabel. heading and transcriptAllowance are text to show as given.

  1. stage-upload: send its fields, fileName and the file's size in bytes as byteLength. It answers 200 with an entity of class upload-staged, a self link to this upload's status, and two actions.
  2. upload-content here is a multipart POST: send every field it lists with the value it carries, then the file in the file field, last. Storage answers 201. The same action name on an upload slot is a PUT, so follow each action's own method, type and fields.
  3. confirm-received: submit it once storage has answered. It answers 303 to the reader's collection, where the file appears.

If your app stops between steps, fetch the self link you kept. While the file is still to be confirmed it answers upload-staged again, with confirm-received. Once the file is saved it answers 303 to the collection, and when Readplace can't open the file it answers 422 upload_failed.

A refusal is an error entity. An expired or invalid token answers 401 invalid-token, and a locked account 403. 404 upload_session_not_found means the upload isn't this reader's, or has expired. 409 upload_not_received means storage hasn't got the file yet. 413 upload_too_large means the file is over its kind's uploadCeilingBytes. 422 carries upload_unsupported_type, transcript-quota, transcript-too-long, unreadable-audio, no-audio-track or book-quota, whose retryAt property says when the reader can upload another book.

Mark as read or unread

update-status has one hidden field, status, whose value the server sets to read or unread, so send it as given. It answers 303 back to the collection, which you follow yourself, and it changes the article in every readlist that holds it. It answers 303 even when the article no longer exists, so re-read the collection to confirm.

Follow every redirect yourself, sending the token and the Accept header again. Some HTTP clients drop Authorization when they follow a redirect, and the API then answers 401.

Manage readlists

A readlist is a named list of the reader's articles. All holds every save, and the reader can create up to {{readlistLimit}} named readlists besides it.

  • create-readlist, on every collection: a form with label. It answers 303 to the new readlist's collection, which is where you learn the new readlist's href.
  • rename-readlist, on a named readlist's collection: a form with label. It answers 303 to the renamed readlist's collection. A label another readlist already has gets a number added.
  • delete-readlist, on a named readlist's collection: a form with no fields. It answers 303 to All, and it takes nothing out of All.
  • pin-readlist, on a named readlist's collection that isn't pinned: a form with no fields. It answers 303 to that readlist's collection. The reader can pin up to {{readlistPinLimit}} readlists. Each properties.readlists entry carries pinned, true or false; All is never pinned.
  • unpin-readlist, on a pinned readlist's collection, in place of pin-readlist: a form with no fields. It answers 303 to that readlist's collection.
  • add-to-readlist, on every article, including the one a save answers with: JSON with readlists, hrefs of named readlists from properties.readlists. All isn't a target: every article is already in All. Sending no href for a named readlist the reader owns answers 404 unknown-readlist, including when the only href is All's. It answers 303 to page 1 of the readlist and tab its href was built for: the listing the article came from, or All's To Read tab for the article a save answers with. Filing an article in a named readlist that already holds it succeeds.
  • remove-from-readlist, on an article listed in a named readlist: a form with no fields. It answers 303 to the first page of the same readlist and tab, and it takes nothing out of All.

Apart from the 402 and 403 under Errors, which carry messages, a refusal is an error entity with a code and a message:

  • 404 unknown-readlist: the readlist no longer exists, or add-to-readlist named none of the reader's named readlists.
  • 404 unknown-article: the article isn't in that readlist any more, for example because it was already removed.
  • 422 invalid-name: the label is empty or longer than {{readlistNameLimit}} characters.
  • 422 reserved-name: create-readlist was sent the label All, in any letter case.
  • 422 name-taken: for create-readlist, the reader already has a readlist with that label. For rename-readlist, the numbered label would be longer than {{readlistNameLimit}} characters.
  • 422 limit-reached: the reader already has {{readlistLimit}} named readlists.
  • 422 pin-limit-reached: pin-readlist was sent while {{readlistPinLimit}} readlists are already pinned. Unpin one first.

To drain a readlist, take each tab in turn. Open page 1, invoke remove-from-readlist on each article, follow the 303 back to page 1, and repeat until the tab is empty. Removing moves later articles onto page 1, so always start again from page 1 rather than following next.

Caching

  • Collections and Markdown documents answer Cache-Control: private, no-cache. Keep a copy if you like, but revalidate it before you reuse it.
  • A collection, and the 303 that moves an older collection href to its current form, answer Vary: Accept, Authorization, User-Agent, X-Readplace-Client, X-Readplace-Save-Continuity. Key any copy you keep on the token and the Accept header too, so one reader's collection is never served for another's token.
  • An answer may carry an ETag and answer 304 to a matching If-None-Match. That isn't promised, so use it when it's there and don't depend on it.
  • Don't send X-Readplace-Client. It marks Readplace's own apps, and their listings are cached differently.
  • A client installed from an app store may send its storefront's three-letter code in an X-Readplace-Storefront header, or in a readplace_storefront cookie from a web view. For China mainland (CHN), responses leave out text a model wrote: summaries, Next read and Already read.

Errors

Key off the status code, and show any messages as given.

  • 401 on a Siren request: the token is missing, expired or revoked, and the body is a Siren error entity. WWW-Authenticate points to the protected resource metadata with resource_metadata, and adds error="invalid_token" when a token was sent. Refresh the token and try again.
  • 401 on a Markdown read: WWW-Authenticate: Bearer error="invalid_token", with no resource_metadata. Refresh and try again. To find the authorization server from scratch, start from a Siren request.
  • 303 to /login: the request has no Siren Accept header, so Readplace treats it as a browser.
  • 402: the action needs a paid plan, and the reader's account is on the free plan. Saving, readlist changes, reading, listing, marking as read and removing from a readlist keep working on the free plan, within its daily limits.
  • 403: the reader's account is locked. Saving is refused, and so are creating, renaming and deleting readlists and adding articles to them.
  • 404: the article isn't the reader's, a readlist action names a readlist that no longer exists, or add-to-readlist names none of the reader's named readlists. All isn't an add-to-readlist target. A GET of a deleted readlist's href lists All instead.
  • 406: a save sent without the Siren Accept header by a client signed in with a browser session, such as one create-session made.
  • 409: the save was accepted and is still being resolved. Don't send it again.
  • 422: a refusal. The saving and readlists sections list its shapes.
  • 429: too many requests. A shared throttle covers every route, with no per-client quota, and /oauth/register and /oauth/token also limit each IP address. A save over the free plan's daily limit answers 429 with the code daily_save_limit. Back off and try again, after Retry-After when it's sent.
  • 500: something failed on Readplace's side. Try again later.

WWW-Authenticate: Bearer error="invalid_token", resource_metadata="https://readplace.com/.well-known/oauth-protected-resource"

Limits

  • Up to {{readlistLimit}} named readlists, besides All.
  • Readlist names up to {{readlistNameLimit}} characters.
  • Up to {{inlineFileLimit}} per file sent with save-content. A larger file goes through an upload slot.
  • Up to {{pdfUploadLimit}} per PDF and {{htmlUploadLimit}} per HTML page through an upload slot.
  • Up to {{requestLimit}} per save-content or save-articles request.
  • Up to {{bulkPageCount}} pages per save-articles request, each up to {{bulkPageLimit}}.

Each action also states its limits in its fields, as maxItems, maxBytes and maxRequestBytes, Readplace's own additions to Siren's fields. Read them from the answer rather than hard-coding these numbers.

Not in the API

  • Deleting an article stays in the Readplace app. The API advertises no delete action, and remove-from-readlist takes nothing out of All.
  • No webhooks or feeds. Poll the collection to see what changed.
  • No full-text search. search narrows by status, order, page and URL only.
  • No page-size control. The server picks the page size.

Walkthrough: drain a readlist

A job that files links into a readlist and later works through them, end to end:

  1. Register once, with a loopback redirect URI on the port your job listens on.
  2. Send the reader to authorize with a PKCE challenge, catch the code on your redirect URI, and exchange it for tokens. Store both.
  3. Request / with the token and the Siren media type. It answers with the collection.
  4. Invoke create-readlist with a label, once, and follow its 303. On the collection it lands on, the new readlist is the properties.readlists entry with the rel current. Keep its href.
  5. Save each link with save-article, sending that href in readlists.
  6. Later, follow the readlist's href. For each entry in its properties.tabs, open that tab's page 1. For each article, follow read with the Markdown media type, hand the document on, and invoke remove-from-readlist. Follow the 303 back to page 1, and repeat until the tab is empty.
  7. All still holds every article you saved.
  8. When a request answers 401, refresh the token, store the new pair, and send the request again.
