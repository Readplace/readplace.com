# Next read checks runbook

Next read waits for a reader's capture before it compares a save, and recomputes a skipped save once its content lands. Both behaviours were verified by dated checks on GitHub issues. This page holds those checks so a later run repeats the same queries, windows and pass bars. Production access follows CLAUDE.md, AWS Accounts. Everything posted on an issue is counts only: the repository is public, so no urls, reader ids or titles.

## Query conventions

- **Running queries.** Write each query to a scratchpad file and pass `--query-string file://<path>`, so shell quoting cannot change it. Convert times with `date -u -j -f "%Y-%m-%dT%H:%M:%SZ" <iso> +%s`.
- **Windows** start 5 minutes after their day 0, so lines from code that predates the deploy do not enter the window.
- **Line format.** Lines are util.inspect text, such as `url: '…'` and `receiveCount: 3`.
  - A value that holds a single quote is double-quoted. The floor reason, "no earlier save shares the saved article's words", is one. Parse `reason` both ways (`/reason: '(?<r1>[^']+)'/` and `/reason: "(?<r2>[^"]+)"/`) and take `coalesce(r1, r2)`.
  - If a parse leaves a field empty on every row, print three raw lines (`fields @message | limit 3`) and fix the pattern before you conclude anything. The crawl-pipeline-rca skill covers blank Logs Insights columns.
- **Exclusions.** Exclude the canary with `@message not like /crawl-canary\/upload\//`. Exclude recompute lines from the day-7 wait queries with `@message not like /trigger: .content-changed./`.
- **Lines from parallel plans.** Other plans add lines to the same log group: the SDK lines. These queries filter on exact message prefixes, so those lines never match.
- **Table key.** Compute it with the package's built output: `ArticleResourceUniqueId.parse(url).value` from `src/packages/article-resource-unique-id/dist`, called from a short `node` script. Never port the rule to another language: a Python port missed 220 of 1,462 urls on 2026-11-01.

- **Joins.** The tables are `hutch-articles-cda0a08` (key `url`; readerAvailableAt is stamped once, when the article first becomes ready, `src/packages/domain/src/article-aggregate/reader-availability.ts:10-16`) and `hutch-user-articles-8226beb` (`url-index`). Join scripts hold urls in memory only and print counts. Run them as `env -u AWS_ACCESS_KEY_ID -u AWS_SECRET_ACCESS_KEY -u AWS_SESSION_TOKEN AWS_PROFILE=hutch-production AWS_REGION=ap-southeast-2 python3 -I <scratchpad script>` (CLAUDE.md "AWS Accounts"), or feed them the JSON output of the prefixed aws CLI; without that environment a script reads the default staging credentials.

## Capture-title count, day 28

- **Rule.** Write a capture-title plan only if, in the 4 weeks after the wait's day 0, 28 or more stub-reason skips with `crawlStatus: 'ready'` (canary and recompute lines excluded) fall on a target whose capture logged a `capturedTitle` that is neither empty nor the host. That is one a day.
- **Source of the captured title.** It comes from the `[SaveLinkRawHtmlCommand] tier-0 source written` lines on `/aws/lambda/save-link-raw-html-command-handler`; their `capturedTitle` field is `projects/save-link/src/runtime/domain/save-link-raw-html/save-link-raw-html-command-handler.ts:113`. Match each line to its skip by table key and time, compare titles in memory, and print counts only.
- **Corrected baseline.** About 6 stub skips on ready crawls whose target was readable more than 60 s before the skip in the 10.9 days to 2026-10-24. That is about 15 per 4 weeks, before the captured-title filter. Canary uploads are excluded.
- **Population changes:**
  - path-less plain-text resources are in the population (`finalize-article.ts:203`);
  - the parser still gives a titleless page the stub title (`readability-parser.ts:105`).
- **Timing.** Run on day 28, before day 30, when retention starts dropping the window's first lines. Post "Day-28 count: …" on the dated issue.
